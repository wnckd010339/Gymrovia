# Gymrovia 계정·가입 흐름

## 결정된 사용자 흐름

1. 관리자는 배포 시 한 번 생성한 고정 로컬 계정으로 로그인한다.
2. 회원은 로그인 화면에서 홈페이지 회원가입 또는 Google 로그인을 각각 선택한다.
3. 회원가입 버튼은 별도의 방식 선택 화면 없이 Gymrovia 자체 회원가입으로 바로 이동한다.
4. 홈페이지 회원가입은 로그인 ID, 비밀번호, 이메일, 이름, 연락처를 입력한다.
5. Google 신규 회원은 로그인 인증 후 이름, 연락처, 약관 동의를 추가 입력한다.
6. 회원은 담당 트레이너 상담 희망 여부를 선택한다.
7. 관리자는 희망 회원에게만 트레이너를 배정한다.
8. 트레이너를 원하지 않으면 활성 배정 행이 없는 상태로 정상 이용한다.

## 인증 데이터 원칙

- `users`에는 공통 사용자·권한·상태를 둔다.
- 로컬 로그인 정보는 `user_local_credentials`에 분리한다.
- Google 계정은 `user_oauth_accounts`에 저장한다.
- Google 외부 식별자는 이메일이 아니라 OpenID Connect의 `sub`를 사용한다.
- 비밀번호는 BCrypt 해시만 저장한다.
- Google Client ID와 Secret은 환경 변수로만 주입한다.

## 화면 흐름

- UI-01 로그인: 일반 로그인, Google 로그인, 회원가입 진입
- UI-02 회원가입: UI-01의 회원가입 버튼에서 바로 이동하는 Gymrovia 자체 가입
- UI-02G Google 최초 로그인 추가 정보: 센터 이용 필수 정보 입력
- MEMBER-V2-01 회원 홈: 가입 완료 후 회원 전용 포털
- UI-05 회원 상세: 관리자에게 가입 방식, 트레이너 희망 여부, 현재 배정 상태 표시

## 구현 우선순위

1. 관리자 seed 계정과 로컬 로그인
2. 회원 일반 가입
3. Google OAuth 로그인과 신규/기존 계정 분기
4. 역할별 로그인 성공 이동
5. 관리자 회원 목록·상세
6. 선택적 트레이너 배정
7. 회원권·결제·출석
8. 운동 루틴·기록
